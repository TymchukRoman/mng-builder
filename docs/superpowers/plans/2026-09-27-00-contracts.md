## Contract B — REST API and WebSocket (server, all under `/api`)

**Conventions:**
- JSON everywhere. Bodies are validated with the §A.3 schemas.
- *(M1 fix wave F13, widened by M2 fix-wave G4)* Host/Origin allowlist (`api/guards.ts`, active once listening): the `Host` header must be `127.0.0.1:<port>` or `localhost:<port>`, and an `Origin` header sent on a WebSocket upgrade or on any non-GET/HEAD request must come from `http://127.0.0.1:<port>` or `http://localhost:<port>`; otherwise 403 `forbidden`. A request with no `Origin` (GET/HEAD, or a non-browser client like the CLI) is not checked. **Dev proxies must rewrite Host and Origin to the server's**: M3's Vite proxy needs `changeOrigin: true` for `/api` and `/files`, and — after M2 G4 widened the Origin check to any non-GET/HEAD request, not just the WebSocket upgrade — it must also set `Origin` to `http://127.0.0.1:4317` on *every* proxied `/api` request (`headers: { origin: SERVER }`), not only on the `/api/events` upgrade.
- Errors are `ApiErrorBody`, with these statuses: `not_found` 404, `validation` 400, `conflict` 409, `needs_confirm` 409 (details `{ removedPanelIds: string[] }`), `engine_unavailable` 503, `forbidden` 403, `internal` 500.
- Every mutation emits a `ServerEvent` of type `entity`.
  - *(M1 fix wave F1)* Cascades emit one event per entity they change, dependents first: character delete → `panel updated` (script/refs stripped), `textFrame updated` (speaker cleared), `character deleted`; reading-direction change → `page updated` per mirrored page (frames are part of the page detail), `manga updated`; page delete → `panel deleted` per panel, `page deleted`, and for a cover `manga`/`chapter updated` (coverPageId cleared); chapter delete → `panel deleted`, `page deleted` (cover included), `chapter deleted`; merge → `panel deleted`, `image updated` per variant moved to the kept panel, `page updated`. Frames and images removed with their page, panel or character are covered by that owner's event.
