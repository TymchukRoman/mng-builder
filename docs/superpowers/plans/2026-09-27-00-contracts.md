# Manga Builder — Plan Index and Cross-Milestone Contracts

**Spec:** `docs/superpowers/specs/2026-09-27-manga-builder-design.md`

This file is the **single source of truth for the names, types and APIs shared between milestones**. Every milestone plan uses exactly these names. If a plan needs something that crosses a milestone boundary and it is not here, add it here first.

## Plans and order

| # | Plan | Repo | Depends on | Ends with |
|---|---|---|---|---|
| P1 | `claude-image-gen/docs/superpowers/plans/2026-09-27-manga-models-upgrade.md` | claude-image-gen | models downloaded | Every new model is usable via `gen.py`; smoke + bake-off; skill updated |
| M1 | `2026-09-27-m1-foundation.md` | manga-builder | — | Monorepo, shared schemas and layout engine, store, REST API (CRUD + layout + text frames), job queue, events, and a `manga` CLI for all non-AI commands |
| M2 | `2026-09-27-m2-ai-imaging.md` | manga-builder | M1, P1 | Engines (claude/ollama), ComfyUI client and recipes, image generate/review/upscale, character refs, AI panel prompts, and the matching CLI commands |

- **UI style rules:**
  - No unnecessary text (use tooltips).
  - Icon buttons instead of labelled ones.
  - Loaders that show a status.
  - Compact layout with consistent spacing.
  - Nothing neon or fancy; clean and tool-like.
  - Neutral colours.
  - Light and dark themes.

```ts
export type IdPrefix = 'mg' | 'cr' | 'ch' | 'pg' | 'pn' | 'tf' | 'im' | 'jb' | 'er';
/** 10 chars from 'abcdefghijklmnopqrstuvwxyz234567' via globalThis.crypto.getRandomValues, e.g. newId('mg') → 'mg_k3j9x2abq7'. */
```

`@manga/shared` is imported by the UI too, so it must never import `node:*` modules. `globalThis.crypto` exists in both Node ≥ 20 and browsers.

- **Every `New*` type is `Omit<Entity, 'id' | 'createdAt' | 'updatedAt'> & { id?: string }`.**
  - The repo assigns `newId()` unless an id is supplied.
  - Panel rows use their layout-leaf id.
  - M2 writes `<imageId>.png` before it inserts the Image row.
- **The `images` repo patch** is `Partial<Pick<Image, 'review' | 'ownerId'>>`. A merge moves the removed panel's variants to the kept panel.
- **`pages.listByManga(mangaId)`** also exists.
- **`domain/delete.ts` also exports `deleteCharacter(store, id)`.** It strips the character from panel scripts, `refCharacterIds` and dialogue speakers.
- **Uploaded JPEGs keep their original bytes** at the `…/<imageId>.png` path, and `/files/images/:id.png` sends the correct content type. Never assume an image file is a PNG: sniff the magic bytes.
- **Import points (barrels):**
  - `packages/server/src/store/index.ts` re-exports every C.1 name.
  - `packages/server/src/jobs/index.ts` re-exports every C.4 name. It must **not** re-export `llm-step.ts` (M2), which imports from the barrel.
  - Later milestones import only from these barrels, plus `events/bus.js`, `domain/*.js` and `app.js`.

**Cascade deletes:**
- Deleting a manga removes its chapters, characters, pages, panels, frames, images and episode runs, plus the manga's image directory.
- Deleting a chapter, page or panel removes its dependents, and the files of the Image rows removed with them.
- This logic lives in `packages/server/src/domain/delete.ts`: `deleteManga`, `deleteChapter`, `deletePage` and `deleteImage(store, id)`.

**M4 episode job lanes:**
- Every episode step runs as `llm.step {type:'episode', runId, step}`.
- LLM steps use `engines.laneFor(task)`.
- `render` and `lettering` are orchestration drivers on lane `cpu` with `maxAttempts: 1`. They wait on GPU and review jobs, so they must never hold the `gpu` lane.
- Because the `cpu` lane has concurrency 1, an export queued while a render driver is running waits for it.

**The exporter:**
- It opens `/render/page/:id?hires=1`.
- It waits for `__MANGA_RENDER_READY__` **or** `__MANGA_RENDER_ERROR__`, and fails at once on the error.

- **`CliContext` also has:**
  - `wait: boolean` (the global `--wait`).
  - `io: CliIo`: stdout/stderr writers plus an optional `AbortSignal`. All output goes through `io`, so commands are testable.
